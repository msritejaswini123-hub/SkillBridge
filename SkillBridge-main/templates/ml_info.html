1. The rule-based engine

This is what your match percentage is

Every student-internship pair is scored on five factors. Each produces a 0–100% sub-score and a sentence explaining itself; the weighted sum is the match percentage.

FactorWeightHow it is measured
Skill match {{ (weights.skills * 100)|int }}% (matched required + ½ × matched preferred) ÷ (all required + ½ × all preferred)
Qualification {{ (weights.qualification * 100)|int }}% Degree is 65% of this factor, branch 35%. “Any Degree” scores full marks. B.Tech and B.E are treated as equivalents.
Location {{ (weights.location * 100)|int }}% Exact city or a remote role scores 100%. A nearby city in the same cluster 85%. A different city 25%.
Stipend {{ (weights.stipend * 100)|int }}% Meets or beats your minimum scores 100%. Below it the score is the ratio — an 8,000 offer against a 10,000 minimum scores 80%.
Experience & projects {{ (weights.experience * 100)|int }}% 40% prior experience (6 months is full marks), 60% whether your projects mention the skills or domain asked for.
Worked example. A B.Tech CSE student in Hyderabad expecting 10,000–20,000 with Python, SQL and HTML, against a Python Developer Intern role in Hyderabad paying 15,000 that requires Python, SQL and Flask: skills 2 of 3 = 66.7% → 33.3 pts, qualification 100% → 20 pts, location 100% → 15 pts, stipend 100% → 10 pts, experience 0% → 0 pts. Total 78%, with Flask listed as missing. Add Flask and a relevant project and the same role scores in the mid-90s.

3. Resume parsing

pypdf extracts the text of every page. That text is matched against a dictionary of canonical skills and their spelling variants, using word-boundary regexes that respect + and # — so C does not match inside “CSE”, but C++ matches itself. Short names such as ML and Go must be capitalised, so the English word “go” is never read as the Go language, and a degree code only counts when written as an abbreviation, so a sentence-initial “It” is never read as the IT branch.

This is a dictionary lookup, not machine learning — which is the point. It is predictable, debuggable, and the student always sees and can correct exactly what was extracted before anything is saved.
